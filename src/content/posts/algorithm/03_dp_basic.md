# 第三章 动态规划基础：状态转移与背包模型

> 动态规划 (Dynamic Programming, DP) 是一种通过将复杂问题分解为**重叠子问题**，并利用**子问题的最优解构建全局最优解**的算法设计思想。其核心是通过“空间换时间”记录历史状态，避免暴力搜索中的重复计算。

## P0：核心考点

### 1.1 动态规划两大核心基石

一个问题能否使用动态规划求解，取决于是否严格满足以下两个特征：
1. **最优子结构 (Optimal Substructure)**：
   原问题的全局最优解必然由其各个子问题的最优解构建而来（具有马尔可夫性：未来的最优状态仅依赖于当前状态，而与过去的形成过程无关，即**无后效性**）。
2. **重叠子问题 (Overlapping Subproblems)**：
   在自顶向下递归求解过程中，相同的子问题会被成百上千次重复计算（如暴力计算斐波那契数列）。动态规划利用数组或表格记录子问题结果，使得每个子问题仅计算一次。

#### 动态规划解题规范五步法
1. **确定 `dp` 数组及下标的物理含义**（例如：`dp[i][j]` 表示容量为 $j$ 时前 $i$ 个物品的最大价值）。
2. **推导状态转移方程**（从前驱状态如何推导当前状态）。
3. **确定初始状态与边界条件**（`dp[0]` 的初始值）。
4. **确定遍历顺序**（保证在计算当前状态时，所依赖的前驱状态已经全部计算完毕）。
5. **推演并验证小规模数据**。

### 1.2 核心手撕 1：0-1 背包 vs 完全背包

背包问题是理解动态规划维数压缩和遍历顺序的黄金标杆。

#### 1. 0-1 背包（每个物品最多选 1 次）
* 二维状态转移方程：
  $$dp[i][j] = \max(dp[i-1][j], \, dp[i-1][j - w[i]] + v[i])$$
* **一维空间压缩核心**：
  $$dp[j] = \max(dp[j], \, dp[j - w[i]] + v[i])$$
  **容量必须从大到小【逆序遍历】！**
  - **原因**：当前状态 $dp[j]$ 需要依赖**上一轮尚未放入该物品的旧状态** $dp[j - w[i]]$。若正序遍历，$dp[j - w[i]]$ 会被提前覆盖为“已经放入过当前物品的新状态”，导致同一物品被多次错误累加。

```cpp
#include <vector>
#include <algorithm>

int knapsack01(int W, const std::vector<int>& weights, const std::vector<int>& values) {
    int n = weights.size();
    std::vector<int> dp(W + 1, 0);

    for (int i = 0; i < n; ++i) {
        for (int j = W; j >= weights[i]; --j) { // 核心：逆序遍历防重选
            dp[j] = std::max(dp[j], dp[j - weights[i]] + values[i]);
        }
    }
    return dp[W];
}
```

#### 2. 完全背包（每个物品可选无限次）
* **一维空间压缩核心**：
  **容量必须从小到大【正序遍历】！**
  - **原因**：完全背包恰恰允许同一物品被多次重复放入，当前状态需要复用本轮已经更新过的状态。

```cpp
int completeKnapsack(int W, const std::vector<int>& weights, const std::vector<int>& values) {
    int n = weights.size();
    std::vector<int> dp(W + 1, 0);

    for (int i = 0; i < n; ++i) {
        for (int j = weights[i]; j <= W; ++j) { // 核心：正序遍历允许重复选取
            dp[j] = std::max(dp[j], dp[j - weights[i]] + values[i]);
        }
    }
    return dp[W];
}
```

### 1.3 核心手撕 2：最长递增子序列 (LIS, LeetCode 300)

* **定义**：找到数组中最长严格单调递增子序列的长度。
* **解法 1：经典动态规划 $O(n^2)$**
  `dp[i]` 表示以 `nums[i]` 结尾的最长递增子序列长度：
  $$dp[i] = \max(dp[j] + 1), \quad \text{for } 0 \le j < i \text{ 且 } nums[j] < nums[i]$$
* **解法 2：贪心 + 二分查找 $O(n \log n)$（大厂高频加分项）**
  维护一个 `tails` 数组，`tails[k]` 存储长度为 $k+1$ 的递增子序列中**最小的末尾元素**。遍历每个数时，通过二分查找（`lower_bound`）更新该元素能够替换或追加的位置。

```cpp
#include <vector>
#include <algorithm>

int lengthOfLIS(const std::vector<int>& nums) {
    std::vector<int> tails;
    for (int x : nums) {
        auto it = std::lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) {
            tails.push_back(x); // 比所有现有结尾都大，扩展最长长度
        } else {
            *it = x;            // 贪心替换为更小的值，为后续元素留出更大上升空间
        }
    }
    return tails.size();
}
```

### 1.4 常见面试问答要点

* **Q：贪心法与动态规划的本质区别是什么？**
  > **回答要点**：贪心算法在每一步决策时做出**局部最优选择**，做出选择后绝不后悔回溯，依赖于“贪心选择性质”；而动态规划会保留所有历史阶段的计算结果，并在状态转移中通过 `max`/`min` 对比所有可能的候选决策，最终全局挑选出综合最优路线。若问题具有重叠子问题但局部最优不代表全局最优，必须采用动态规划。

* **Q：什么是动态规划的“无后效性”？**
  > **回答要点**：某个阶段的状态一旦确定，该状态就完整涵盖了该系统历史发展的所有必要信息，**未来的决策仅取决于当前的状态值，而与过去是通过何种路径演进到该状态的完全无关**。若状态中隐式依赖了到达该点的具体路径细节，则必须将这些细节显式升维编入状态定义中，否则 DP 将无法正确递推。

## P1：经典模型与空间压缩

### 2.1 编辑距离 (Edit Distance, LeetCode 72)

* **状态定义**：`dp[i][j]` 表示将字符串 $A[0..i-1]$ 转换为 $B[0..j-1]$ 所需的最少操作次数（插入、删除、替换）。
* **状态转移方程**：
  - 若 $A[i-1] == B[j-1]$：字符相等无需修改，`dp[i][j] = dp[i-1][j-1]`。
  - 否则取三种操作的最小值加 1：
    $$dp[i][j] = 1 + \min(\{dp[i-1][j], \, dp[i][j-1], \, dp[i-1][j-1]\})$$
    其中 `dp[i-1][j]` 代表删除，$dp[i][j-1]$ 代表插入，$dp[i-1][j-1]$ 代表替换。

---

### 2.2 零钱兑换 (Coin Change, LeetCode 322)

* **完全背包求极小值变体**：
  `dp[j]` 表示凑足金额 $j$ 所需的**最少硬币数**。
  $$dp[j] = \min(dp[j], \, dp[j - \text{coin}] + 1)$$
  初始状态除 `dp[0] = 0` 外，其余全部初始化为极大值 `INF`。

## P2：工程实践与业务场景

1. **游戏装备负重与词条收益最优化**：限定角色最大负重 $W$（背包容量），各装备有重量与综合战力评分，采用 0-1 背包求出最大属性收益组合。
2. **文本输入拼写提示**：基于编辑距离算法，当玩家在聊天框输入未命中字典的词汇时，计算其与敏感词或常用词库的编辑距离，若 $\le 2$ 则触发纠错建议。
